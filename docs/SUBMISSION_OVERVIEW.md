# 研舟 ResearchDock 作品介绍

参赛姓名：穆宣廷

学校：太原科技大学

## 01 项目详情与使用说明

研舟面向科研论文阅读和材料整理，将 PDF 文献管理、证据问答、双语阅读、论文发现、引用分析和写作绘图整合到同一工作台。系统保存原始 PDF、页码、文本区域与引用关系，使回答、公式和图谱中的信息可以回到原文核读。

典型使用过程：登录工作台，批量导入论文并查看解析状态；打开文献阅读章节、作者、摘要和公式；选择单篇或多篇文献提问，并点击出处；检索相关论文、查看引用图谱；整理写作框架、译文或 CSV 数据图表。

在线演示：https://39.105.29.231

源码仓库：https://github.com/tmu0856-eng/-

## 02 项目亮点

文献与结果相连：问答保存证据页码和区域，正文引用与参考条目可双向跳转，图谱连边保留出处，公式关联原始页面、转录与修改记录。

追问与范围相连：后续问题可承接已引用文献，参数对象不明确时先澄清；回答时重新检索原文，多文比较分别保留各篇证据。

阅读与整理相连：论文导入后可直接进入阅读、翻译、引用分析和写作模块；已有识别结果、译文与检索结果可缓存复用。

配置与环境相配：本地配置支持 BGE-M3 与 reranker，云端配置采用远程 MiMo 接口和词项检索，分别提供环境模板与 Docker 启动方式。

## 03 AI 技术落地与测试情况

MiMo mimo-v2.6-pro 通过兼容接口接入文本回答、工具调用与页面视觉识别。Agent 按规划、核读和综合阶段调用文献列表、原文搜索、指定页读取及用户开启后的 arXiv 发现工具，后端校验工具参数与文献范围。

本地检索将 BGE-M3 的 1024 维 dense 向量与 BM25、TF-IDF 候选通过 RRF 合并，再由 bge-reranker-v2-m3 精排。云端采用 MiMo 远程接口、BM25 与 TF-IDF，并持久化保存文献及已有向量缓存。模型配置明确区分运行环境。

验证记录包括：275 项自动回归通过；资料包 39 份 PDF、1,986 页的 32 项真实流程检查通过；专项扩展至 40 份 PDF、2,010 页；公网 HTTPS、评审登录、扫描解析、SSE、重启持久化与完整题名检索已分别核验。自动回归与真实模型调用分开记录，样本规模与各项结果均可在源码 docs 目录复查。

## 04 项目关键技术

FastAPI 与 SSE 提供接口、异步任务状态和流式返回；SQLite WAL 保存文献、证据、任务与缓存。PyMuPDF 保留原始页图、文本块与 bbox；OCR 处理图像扫描页；目录结合原生结构、编号、字号和几何信息组织。

证据问答在服务端管理文献范围、来源编号与引用原句，回答可按页和区域回跳。公式采用本地 KaTeX 排版，支持原图对照、修改、保存和恢复；分页修订号用于处理过期保存。arXiv 缓存包含检索式、排序和字段范围，图谱采用真实参考条目匹配与局域 PageRank。

云端通过独立 Docker 容器部署，Nginx 提供 HTTPS 与 SSE 反向代理，文献和数据库保存在持久化目录。模型密钥通过环境变量配置，评审账号通过独立渠道提供。
