# 两阶段精排接入与验证

日期：2026-11-15。

## 当前行为

普通问答和 Agent 原文检索均经过：BM25 + TF-IDF + BGE-M3 混合召回 → 本地 `BAAI/bge-reranker-v2-m3` 精排 → 保留调用方需要的证据 → MiMo Pro 基于证据回答。

- 默认最多 40 个候选，配置上限 80；默认 4 条一批，编码上限 512 Token，过长问题/片段会截断。普通问答保留最多 10 条，Agent 按工具参数返回。
- Cross-encoder 直接对问题/片段计算原始相关性 logit；该值不是事实正确率或经过校准的概率。
- 只重新排序现有原文，不生成候选文本；保留文件范围、chunk ID、页码、坐标和内容，最终证据连续编号。保留作者首页证据及跨论文覆盖，受最终证据条数上限约束。
- 精排异常时保留混合召回排序，并在执行记录中显示回退原因。无候选或仅一条候选时不加载精排模型。
- 与本地 Embedding 共享计算锁，精排加载前释放当前进程空闲 CUDA 缓存；避免后台索引和精排同时制造显存峰值。本机 RTX 2070 实际使用 CUDA / FP16。
- 不改动论文原文或已有向量索引；无需重新导入和重建 BGE-M3 向量。本轮没有 Git 提交、推送或赛事提交。

## 验证

- 回归测试 **173 项通过，32.98 秒**。新增检查覆盖扩候选后提升、论文范围、跨文保底、作者首页、引用编号和坐标、模型缓存、分批、安全加载参数、非有限/数量异常评分、无模型和配置错误回退、Agent 检索后读页编号稳定。
- JavaScript 语法和 Python 编译检查通过。
- `scripts/verify_reranker.py` 使用两个真实模型，在独立存储中的 10 段合成证据上比较 8 个中文问题。首条命中 **6/8 → 7/8**，前五条命中 **8/8 → 8/8**，所有返回文本与锚点保留。热启动精排耗时中位数约 **47 ms**，针对该小候选集，不代表 40 个长片段的耗时。另实际模拟文件缺失，确认回退仍返回证据。
- 该样本并非全题改善：“这项研究采用了哪种运算装备”对应硬件证据排名 **2 → 4**；序列顺序问题排名 **3 → 1**。完整逐题排名、候选数和耗时保留于 `RERANKER_CHECK.json`。
- `scripts/verify_reranker_live.py` 对原主库做两次真实 MiMo 调用，普通问答和 Agent SSE 均通过。普通回答包含精排执行记录，GPU/P100 与 Adam beta2=0.98 有原文来源；Agent 执行记录显示“混合召回 → 精排保留”，最终同样有正确来源。SSE 为 20 个 step、16 个 token、3 个 claim、1 个 result，无 error。详见 `RERANKER_LIVE_CHECK.json`。
- 原主库仍为 **28 篇 / 10,299 个已索引文本块**。真实流程最后一次精排 **40 个候选约 469 ms**；冷启动还需模型加载，耗时依候选长度、设备和并发变化。
- 浏览器配置页实际显示两种 CUDA 模型、全部向量就绪、40 候选精排已就绪及最近耗时；截图 `screenshots/reranker-ready.jpg`。

## 复现与限制

安装、下载和 `.env` 设置见 README。`verify_reranker.py` 不调用付费生成模型；`verify_reranker_live.py` 调用现有 MiMo 两次，并使用原主库验证。

小样本提升不等同于资料包整体准确率；尚需扩大真实问题、跨文覆盖、长段落截断及延迟评测。精排不解决 OCR 错误、公式还原或答案的事实蕴含校验。

官方来源：[模型说明](https://huggingface.co/BAAI/bge-reranker-v2-m3)。
