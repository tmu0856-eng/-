## 01  项目用途与功能

研舟 ResearchDock 用于管理论文、检索正文和整理写作材料。系统保存原始 PDF、页码和文本坐标，回答中的引用可跳回原文。功能分为文件管理、论文问答、双语阅读、文献检索、引用图谱和写作绘图六个模块。
| 模块 | 当前实现 | 主要验证边界 |
| --- | --- | --- |
| PDF 管理 | 批量解析、版本提示、作者结构、公式排版与修正 | 复杂版式与所有署名未全面核验 |
| 证据问答 | 多路召回、精排、动态工具与追问 | 引用存在不等于每句话被支持 |
| 对照阅读 | 目录、页图、选段/逐页/全文翻译 | 按滚动比例联动，不是精确段落对齐 |
| 检索追踪 | arXiv 检索、受限下载、主题定时刷新 | 外部可用性与召回完整性不保证 |
| 引用图谱 | 有出处连边、局域 PageRank、综述核验 | 题名匹配仍有漏配及消歧限制 |
| 写作绘图 | 框架、真实条目、架构脚本、CSV 五类图 | 草稿、描述性图注均需人工审核 |

### 使用流程

上传论文并等待解析后，即可提问、阅读译文、查看图谱或生成草稿。重复文献可跳过，也可保留两个版本比较。开发库和评审库使用不同数据目录。

## 02  系统架构与数据流
前端 → FastAPI/SSE → PDF/OCR、检索精排、MiMo → SQLite/本地模型/arXiv（详见 PDF 架构图）。

前端使用 HTML、CSS 和原生 JavaScript；后端采用 FastAPI，SSE 传送真实执行事件与模型增量输出。SQLite 使用 WAL 和外键约束，PDF 文件保存在单独目录。原始页、文本块、区域坐标、引用条目、向量与翻译缓存相互关联。

上传文件先做格式、大小与重复检查，再进入单工作线程逐页解析。原生 PDF 采用 PyMuPDF；图像扫描页使用 RapidOCR 或可用的 Tesseract。解析任务保存逐页进度，服务重启后会将未完成的任务标为中断。

查询走向量、词项与字符特征多路检索，融合后由交叉编码器精排；所选片段与真实页码再传给 MiMo。回答校验使用来源编号与原文引用约束，失败时显示真实错误或证据不足提示。外部检索元信息与本地原文证据分开展示。

### 实现特点

项目使用已有模型，主要工作是文献处理和检索流程的集成：限定检索范围、保存引用出处、校验文献时间、隔离不同模型的向量，并在模型失败时回退到本地检索。未训练基础模型。

## 03  PDF 解析、结构与版本管理

### 结构化抽取

每页保留宽高、文本块与 bbox 坐标，长文档逐页处理。优先使用 PDF 原生目录，结合编号、字号与几何补全三级结构；扫描文本处理缺空格的标题，书籍旁注中的附录交叉引用不当作附录标题。自动估计目录有明确标识，原始页与坐标保留。表格提取保存单元格与原文区域，内嵌图像按区域保存，其中也可能包含扫描整页。

作者机构提取基于首页署名区、几何行序、机构词与邮箱标记。作者姓名、顺序、机构、邮箱及来源区域分项保存；分组邮箱展开会标明来源。用户手工编辑的作者信息不会被静默覆盖。署名区支持一行多作者、机构编号和扫描文本；多机构对应不明时留空。40 份真实 PDF 中 35 份产生署名结构，未逐名全面核准，团体署名与复杂机构对应仍有缺口。

### 内容级重复检测

先比较文件字节哈希、arXiv 编号、版本与正文近似度，再对原生正文的三个采样窗口使用 BGE-M3 编码。文档签名按模型空间缓存，相似度结合题名或编号等条件保守提示。v1 与 v7 实测能识别相关版本并建议保留较新版本。旧文献由用户决定是否保留。扫描文件缺少原生正文时，仅使用已有的文件和词项比较。

### 按页公式与图表识别

阅读页可主动将当前页图片发送给配置的视觉模型，转录 LaTeX、表格单元格与图注。结果缓存并关联原始页面，始终标为未人工核对，不自动注入问答证据。可按候选页建立最多 20 页的批量任务，开始前展示页码及费用提示；成功页缓存，失败页可重试，取消后在当前页完成后停止。MiMo 实测覆盖缩放点积公式、多头注意力公式和 BLEU 表；其他公式、合并单元格和图形描述仍需逐项核对。

识别后的公式采用随应用打包的 KaTeX 0.19.1 排版，和原始 PDF 页图并排显示。可编辑单条 LaTeX 与编号，实时预览、保存并再次读取，也可恢复模型原始转录。修改只更新视觉缓存，保留原始代码与修改时间，不重新调用模型、不进入问答证据。分页修订号用于拦截过期保存；保存一条时保留其他公式的编辑草稿。排版失败时显示文字提示，仍可查看与修改代码。

出版时间来自 arXiv 编号或可核对的出版文字，保留日/月/年精度及来源；PDF 创建时间和导入时间不用于证明出版先后。附录独立列出标题、子章节、页码与原文区域；仍是版式规则估计，不保证所有版式完整识别。已有文献可更新结构，不删除文本块、向量或手工信息。

## 04  模型选择与两阶段检索

本地版支持下表的完整模型组合。当前 1 GB 云端采用独立 Docker 容器，保留 MiMo API 和 BM25 + TF-IDF，未加载本地向量及精排权重。40 篇公开演示文献与 25,464 条已有向量保存在服务器持久化目录；缓存未被删除，但兼容的远程向量编码服务尚未启用。云端不依赖电脑通道，已验证 HTTPS、扫描解析、SSE 和容器重启后数据保持一致。

| 组件 | 选择 | 本项目使用方式 |
| --- | --- | --- |
| 生成 / 工具 / 视觉 | mimo-v2.6-pro | 兼容接口、原生工具、JSON 输出、单页图像输入 |
| 语义向量 | BAAI/bge-m3 | 本地 dense 1024 维；CLS + L2；默认截断 512 tokens |
| 精排 | BAAI/bge-reranker-v2-m3 | 本地交叉编码器，对查询和候选块联合打分 |
| 本地检索 | BM25 + TF-IDF | 与语义通道融合，模型不可用时仍能检索 |

召回通道通过倒数排名融合（RRF）合并。默认最多 40 个候选进入 reranker，再按调用路径截取最终证据；Agent 每次工具检索限制数量。来源编号在最终证据集合中重新分配，保留原文本、页码和区域。作者问题保留首页证据，多文问题保留跨论文覆盖及请求的上下文指标；表格数值问题补充原生同页表头和说明，并使用整页来源区域。

本项目使用 BGE-M3 的 dense 向量，未启用稀疏输出或 ColBERT 多向量。默认最大长度为 512 tokens，用于控制显存和耗时；较长片段会截断。向量以 float32 BLOB 保存，检索时按模型空间匹配；更换模型需重新建索引。

向量模型与精排模型共享推理锁，降低后台索引和前台请求同时计算时的显存峰值。本机使用 CUDA FP16；无 GPU 可采用 CPU 配置，但云主机 CPU 双模型延迟尚未测量。

### 小样本排序结果

八道合成排序题：首条命中从 6/8 到 7/8，前五条均为 8/8；其中一道硬件问题从第 2 名下降到第 4 名。小候选集预热后精排中位数约 47 ms，一次真实 40 候选约 469 ms。结果来自本机小样本，适用范围有限。

## 05  论文问答与工具调用

系统支持直接检索与自主工具调用两种路径。Agent 分为规划、核读和综合三个阶段，均由同一模型执行。实际工具包括文献列表、范围内原文搜索、指定页读取，以及用户明确开启后的 arXiv 发现；工具不执行任意代码，也不自行删除或导入论文。

工具参数由后端校验，范围由后端锁定，来源编号跨工具调用保持稳定。设有轮次、调用次数、证据数量和时间预算，重复或无效调用被跳过或停止。前端显示实际工具名称、参数及结果，不展示模型私有推理。

### 多轮追问

前端提交有限的近期对话；后端只在检测到追问且前次来源仍存在时继承已引用的文献范围。显式选择的不同范围优先，新主题不盲目继承。上一轮生成的答案不作为新的证据，后续问题仍须重新查原文；删除的来源要求用户重新选文献。参数对象只从用户问题确定，多个可能对象先澄清；用户短答对象名后继续处理原问题，新主题不会继承更早的对象。真实 epsilon 追问重新定位 v7 第 7 页并回答 Adam 的 10⁻⁹。

### 证据约束与流式输出

模型输出按结构化声明解析。未完成校验的流式内容只作生成过程提示，来源编号与逐字原句检查通过后才展示为有出处的声明。模型无法给出有效来源、输出截断或外部服务失败时，保留执行状态并如实提示。

引用编号存在只能证明来源记录存在，不能独立证明每个结论的语义蕴含。因此系统保留原文回跳，仍要求核读。样例验证涵盖 GPU、Adam 参数、作者机构、无原文支持的硬件序列号、BERT 对比与 Agent 综合；其余问题尚未做完整的事实支持评估。

## 06  阅读、检索与写作

### 阅读与翻译

左侧原始页图、右侧可选择文本或译文；目录和证据可跳页，数字引用保存独立正文锚点，可打开条目原文区域高亮，并从条目反查每处正文引用。返回恢复原按钮焦点、两栏滚动、页码与已有译文；同页重复编号不会合并成同一个位置。组合和范围编号支持展开，重复参考编号标为候选匹配；作者年份制和 OCR 缺失括号仍有限制。支持选段、当前页、后台逐页全文翻译及 Markdown 导出。已有页译文按模型缓存，数值、公式和代码要求尽量保留。

原文和译文按滚动比例联动，尚未实现句子或段落对齐，也没有悬停翻译。扫描识别、中文换行、跨页与复杂表格可能影响对照体验。公开演示默认限制全文翻译页数，避免对长书意外发起大量调用。

### 文献检索、追踪与引用入库

arXiv 查询使用真实接口，默认保留上游相关性顺序；最新发表和文献库推荐分别选择，可限定标题字段。连续题名与引号短语保留，修复拆分常用词导致完整题名漏检的问题。缓存包含排序、范围与策略版本，避免将旧版最新候选误用到相关性检索。真实公网题名和编号检索均将 1706.03762v7 定位为首条。接口具备有限重试、缓存时间标签、官方地址校验和错误提示。用户可配置定时主题刷新并保存反馈；推荐使用查询相关性和本地反馈，未使用多用户协同过滤。

参考文献列表标记本地匹配文献。带可识别 arXiv 编号的条目可一批选择 1-5 篇下载，逐条记录已存在、下载成功或失败，之后等待解析。不含可靠编号的条目提供检索入口；未实现对所有 DOI、出版社或题名变体的自动全文解析。

### 写作与数据绘图

生成论文框架、文献综述和 Mermaid 架构图脚本；References 由实际库中条目组装，缺失作者或年份明确标记待核对。生成脚本不会自动执行。支持中英学术翻译。

CSV 输入校验后生成折线、柱状、散点、雷达和三维雷达图，提供 PNG、SVG、Python 脚本与数据下载。图注描述上传的数据，不提供统计显著性或因果判断。Mermaid 当前输出脚本，未内嵌完整图编辑器。

## 07  引用图谱与时间核验

引用图基于本地 References 中的规范化题名匹配。边保存引用方、被引方、原始页码及证据片段，供点击回查。PageRank 仅表示当前文献集合内的结构指标，不等同于全领域影响力或学术质量。

本轮 39 篇资料构成的图谱有 261 条带出处连边，全部文献均检测到参考文献区。此前 20 篇交叉引用样本中有 72 条组内边。检查确认了边和出处存在，尚未给出完整的连边精确率、召回率；同名、版本、DOI 和变体题名仍可能误配或漏配。

### 图谱驱动的综述

综述提示输入真实的范围内引用边和重新计算的局域 PageRank，要求根据实际文献组织关系。References 最终使用库内真实条目重建，避免模型随意增加不存在的文献。元数据缺失时不会补造作者和出版年。

### Future Work 核验

候选方向必须来自含有未来研究标记的原文段落。“已解决 / 部分解决”必须包含候选论文的逐字原句，且出版日期能确认晚于原方向。明显更早的文献被排除，年份精度重叠、时间未知或缺逐字证据时降为待核实。导入时间不参与新旧判断。

可选“联网核查最近研究”最多查询三个方向，将主题关键词发送给 arXiv。返回内容仅作为摘要级线索，不据此断言已解决；无命中只表示本次查询未找到候选。该新增分支已有格式与时间约束测试，尚未完成大规模人工方向核读或穷尽性评估。

## 09  部署、访问控制与运行边界

云端入口为 https://39.105.29.231。Ubuntu 24.04 服务器运行独立 Docker 容器，Nginx 提供 HTTPS 和 SSE 反向代理；仅 80、443 与 SSH 端口对外开放，应用端口绑定服务器回环。电脑关闭后，云端仍可运行。证书自动续期定时器已配置，staging dry-run 通过。

云端采用 compose.cloud.yaml，容器限制 640 MiB 内存、只读根文件系统和独立持久化目录，主机配置 2 GiB swap。保留 40 篇公开文献与 25,464 条向量缓存；当前使用 MiMo API 与 BM25 + TF-IDF，不在 1 GB 服务器加载本地 BGE 双模型。后续兼容的远程向量接口须核对模型空间、维度与归一化方式，不能把不同接口产生的向量直接混用。

新增独立 /login 页面，提供密码显隐、错误与超时提示、账号帮助和移动端布局；未登录访问跳转登录页，登录后回到工作台。接口、本地浏览器流程以及公网匿名跳转、登录退出均通过。

评审 Cookie 使用 HMAC 签名、HttpOnly、Secure、SameSite=Strict 和 8 小时有效期。匿名只能访问健康检查、登录和静态资源，文献数据及模型操作需要登录。代理来源限定到实际 Docker 网关与回环地址，避免任意信任转发头。默认登录与模型操作设有限额；请求限额不能替代服务商总费用控制。

容器启用自动重启；已验证 HTTPS 登录、真实 Agent/SSE、扫描 PDF 解析和重启后数据保留。SQLite 使用在线备份，更新前备份数据库并保留旧镜像。服务器持续运行、磁盘空间、证书与模型服务额度仍需维护。
