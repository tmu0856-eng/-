版本日期：2026-11-16

## 01  项目概述与需求分析

研舟 ResearchDock 是面向科研论文阅读与材料整理的全栈 Web 应用。系统以原始 PDF 为依据，将文献管理、结构解析、证据问答、双语阅读、论文发现、引用分析和写作绘图放在同一个工作台中。使用者从导入论文开始，可连续完成查找原文、比较结论、梳理引用关系和组织写作材料。

科研阅读中的关键需求包括：管理同一论文的不同版本；在双栏页面、表格与公式中找到所需信息；跨论文比较时保留各自出处；阅读过程中快速往返正文与参考文献；将文献关系与原始实验数据整理成可复查的文字和图表。项目围绕这些需求保存原始文件、页码、坐标、参考条目和操作状态，使结果可以回到原文核读。

| 功能模块 | 主要功能 | 交互输出 |
| --- | --- | --- |
| PDF 管理与解析 | 单篇/批量导入、后台逐页处理、版本检查、OCR、三级章节结构 | 文献列表、解析进度、作者机构、摘要、表格、附录与原文定位 |
| 证据问答 | 文献范围选择、原文检索、Agent 工具调用、跨文比较、追问消歧 | 流式状态、执行记录、带编号的回答与出处回跳 |
| 对照阅读 | 原始页图、目录导航、选段/当前页/全文翻译、数字引用双向跳转 | 原文与译文对照、滚动联动、译文缓存及导出 |
| 文献发现 | arXiv 题名/关键词/编号检索、排序选择、主题追踪与反馈 | 论文卡片、摘要、原始链接、下载入库与追踪主题 |
| 引用分析 | 带出处的引用关系、局域 PageRank、综述及未来方向分析 | 交互图谱、节点关系、引用回查与真实 References |
| 写作绘图 | 论文框架、架构脚本、学术翻译、CSV 五类图表 | 草稿、图注、PNG/SVG、Python 脚本与 CSV |

## 02  系统架构与数据流

系统由浏览器前端、FastAPI 后端、SQLite 数据库、PDF/OCR 处理管线、模型接口和 arXiv 连接组成。前端按模块组织页面，通过 HTTP 获取数据，通过 SSE 接收任务与生成状态。后端负责文献范围、工具参数、来源编号与持久化写入，模型接口负责文本生成、工具调用和页面视觉识别。

详见 PDF 架构图。

上传文件后，后端先检查格式与重复情况，再通过单工作线程逐页解析。每页保存文本块、页面尺寸和 bbox 坐标，并与文献、章节、参考条目、视觉识别缓存和译文建立关联。SQLite 使用 WAL 模式，原始 PDF 与生成文件存放在独立数据目录。

问答流程分为范围确定、候选检索、证据整理、模型生成、来源校验和结果呈现。Agent 路径可反复调用文献列表、正文搜索和指定页读取；用户开启联网发现后，可以调用 arXiv 工具。后端设置轮次、工具次数、证据数量和时间预算，记录实际工具参数与执行结果。

## 03  模型选型、集成与优化

| 组件 | 模型或方法 | 选型理由与集成方式 |
| --- | --- | --- |
| 文本、工具与视觉 | mimo-v2.6-pro | 统一兼容接口接入回答、工具调用、JSON 输出及单页图像识别，配置通过环境变量注入 |
| 本地语义编码 | BAAI/bge-m3 | 将问题和原文编码为 1024 维 dense 向量，辅助匹配不同表述；按模型空间保存缓存 |
| 本地证据精排 | BAAI/bge-reranker-v2-m3 | 联合读取查询与候选原文，在召回后重新计算相关性 |
| 词项检索 | BM25 + TF-IDF | 保留专业名词、型号、论文编号和参数的直接匹配能力；用于轻量云端运行 |
| 融合与关系分析 | RRF、局域 PageRank | 合并多路候选，并在当前文献引用网络内组织阅读顺序 |

本地配置采用语义、词项与字符特征多路召回，通过倒数排名融合合并候选，再由交叉编码器精排。默认最多 40 个候选进入精排；作者问题保留首页信息，多文问题保留跨论文覆盖，表格问题补充同页表头与解释。

云端使用独立轻量配置：MiMo 远程接口、BM25 + TF-IDF、本地数据库与持久化缓存。当前服务器保存 40 篇文献和 25,464 条既有向量。向量缓存按模型空间管理；本地完整检索配置与云端轻量配置使用各自明确的启动参数。

长文档逐页解析，前端按需加载页面。向量模型与精排模型共享推理锁；视觉识别与译文按页及模型缓存。外部查询缓存包含检索式、排序方式、字段范围和策略版本，防止不同检索模式互相复用结果。

## 04  文献解析、版本检查与公式整理

原生 PDF 通过 PyMuPDF 提取文本块、坐标与嵌入图像；扫描页接入 RapidOCR 或可用的 Tesseract。章节结构优先采用原生目录，结合编号、字号与几何信息补充一级至三级标题。首页署名区分项保存作者顺序、机构、邮箱与来源区域；摘要、表格、参考文献及附录分别提供结构入口。

版本检查综合使用文件哈希、arXiv 编号、版本和正文近似度。本地语义配置对原生正文的三个采样窗口编码，缓存文档签名，并结合题名和编号生成相似提示。真实 v1/v7 样例可显示已有版本和保留建议，由用户选择处理方式。

阅读页可将当前页图像提交给视觉模型，转录 LaTeX、表格和图注，并保存逐页缓存。公式使用本地打包的 KaTeX 排版，与原始 PDF 页图并排呈现。用户可修改单条公式及编号，实时预览、保存、重新打开或恢复原始识别内容。分页修订号拦截过期保存，同页其他公式的编辑草稿可继续保留。

公式候选页支持建立批量任务，一次选择最多 20 页，并提供缓存复用、失败重试、停止后续页与进度显示。原始转录和人工修改分别保存，便于回查修改过程。

## 05  证据问答与自主工具调用

直接检索路径将选定文献中的候选证据交给模型；Agent 路径按规划、核读与综合阶段调用工具。三个阶段由同一配置模型执行，工具调用由后端校验。工具只接收规定字段，文献范围在服务端锁定，来源编号跨调用保持一致。

模型按结构化声明输出回答，后端检查来源编号及引用原句，再呈现带出处结果。前端展示实际执行状态和工具记录，点击来源可进入对应文献、页码及区域。页面视觉缓存与原文问答证据分开保存，使正文证据来源可追溯。

多轮追问提交有限的近期上下文。追问可承接上轮已引用文献，显式重新选择的范围优先；后续回答重新检索原文。参数名称对应多个对象时，先询问具体对象；收到短对象回复后继续处理原问题。实测 Adam epsilon 追问重新定位 Attention v7 第 7 页，回答为 10⁻⁹。

## 06  阅读、文献发现与引用图谱

对照阅读左侧保留原始 PDF 版式，右侧显示可选文本或译文。支持选段、当前页、后台逐页全文翻译和 Markdown 导出；译文按模型缓存。两侧通过滚动比例联动。数字引用保留独立正文锚点，条目可反查每处引用，返回时恢复页码、滚动和焦点。同页重复引用、组合编号与范围编号分别保留定位信息。

arXiv 检索提供相关性、最新发表与文献库推荐模式，可选择全部字段或标题范围。相关性模式保留上游顺序，连续题名和引号短语按对应方式构造查询。公网实测完整题名 Attention Is All You Need 及编号均可定位 1706.03762v7。结果展示作者、时间、摘要、抓取时间和原始链接；含可识别 arXiv 编号的参考条目支持批量选择下载。主题追踪保存刷新间隔与反馈。

引用图谱根据参考条目和规范化题名匹配建立关系，边保存引用方、被引方、原始页码及片段。当前资料包 39 篇论文构成 261 条带出处连边。局域 PageRank 在当前集合内计算，图谱可查看节点关系并回到出处。综述输入所选论文、真实引用边及局域排名，References 由实际库条目重建。Future Work 分析结合原始方向文字、出版时间及后续研究的逐字证据。

## 07  写作辅助与数据可视化

写作模块围绕给定想法生成包含 Abstract、Introduction、Related Work 和 References 的框架，并提供领域综述、Mermaid 架构脚本与中英学术翻译。参考条目从已导入文献中组装；来源可继续回查。

CSV 输入经字段和数值校验后，支持折线、柱状、散点、雷达及三维雷达图，输出描述趋势的图注，并提供 PNG、SVG、Python 绘图脚本与 CSV 下载。演示视频使用随附的示例数据展示绘图流程，数据文件在提交包中单独标明用途。

## 09  部署与评审使用

在线入口：https://39.105.29.231。源码仓库：https://github.com/tmu0856-eng/-。登录账号通过评审专用文件提供。

Ubuntu 24.04 主机运行独立 Docker 容器，Nginx 提供 HTTPS 与 SSE 反向代理。应用端口绑定回环，容器使用只读根文件系统、独立数据目录和自动重启策略。证书续期定时器已配置并通过 staging dry-run。SQLite 在线备份与原始 PDF 备份共同保存数据，更新前保留数据库备份及旧镜像。

独立登录页支持密码显隐、状态提示和移动端布局。评审 Cookie 使用 HMAC 签名、HttpOnly、Secure、SameSite=Strict 与 8 小时有效期。接口按请求类型设置限额，代理来源限定为实际 Docker 网关及回环地址。模型密钥和账号通过私有环境文件配置，源码与镜像排除密钥、论文数据及模型权重。

评审操作建议：登录后查看文献库，打开 Attention v7，通过章节与引用导航核读；询问训练设备和 Adam 参数并点击出处；查看公式排版与保存；使用完整题名检索目标论文；进入引用图谱与写作模块，最后用示例 CSV 生成图表。

## 10  技术特点、开发过程与总结

项目的应用设计围绕“证据连续性”展开：回答保留页码与区域，正文引用保存独立锚点，公式将原图、转录和修改记录关联，图谱边保存出处，综述引用实际条目。使用者可以从生成结果回到原始材料，再继续阅读和整理。

工程实现将文献范围控制、参数追问、模型空间缓存、来源编号校验和逐字原句检查放入服务端流程；本地完整模型与轻量云端采用分配置部署。项目集成已有模型及公开算法，技术贡献集中于文献处理、证据组织与交互流程。

开发过程中使用 Codex 辅助代码编写、调试、测试与文档整理，并通过真实 PDF、接口和浏览器操作检查交付结果。运行时使用的模型、第三方组件与开源依赖分别在模型配置、依赖文件及相关许可证中说明。仓库保留可追溯的代码变更记录，私人对话、密钥与本机配置单独管理。

研舟以完整前后端、独立云端服务、技术说明和真实操作演示组成作品交付。围绕不同学科资料扩充样本、按实际使用反馈优化证据组织与交互流程，是系统后续应用扩展的方向。
