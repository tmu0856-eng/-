# 本地 BGE-M3 接入与验证

日期：2026-11-14。

后续更新：2026-11-15 已接入本地两阶段精排，见 `RERANKER_CHECK.md`。下文保留最初 BGE-M3 接入时的验证范围。

## 实际启用配置

- 模型：BAAI/bge-m3，官方仓库 revision `5617a9f61b028005a4858fdac845db406aefb181`。
- 权重 2,271,145,830 字节，SHA-256 `b5e0ce3470abf5ef3831aa1bd5553b486803e83251590ab7ff35a117cf6aad38`，下载完成后与官方 LFS 元信息核验一致。
- Sentence Transformers 在本机 RTX 2070 上使用 CUDA / FP16；CLS 池化、L2 归一化、1024 维稠密向量。当前输入上限 512 Token，超长块会截断。
- BM25、TF-IDF、BGE-M3 分别按有效相关性参与 RRF 融合，保留多文范围及页码/区域锚点；每一路不会给零匹配文档无依据的排序票。
- 向量与模型空间标记存储于 `chunk_vectors`，使用 float32 二进制；模型 revision 或编码长度变化后不使用旧空间向量。原 `chunks.embedding` 无模型标记的旧向量不混用。
- 已有和新导入论文可后台补建，按批提交，中断后续建；论文删除会级联删除向量。错误会显示，并允许词频检索继续工作。
- 模型文件、实际 `.env`、数据库和迁移前本地备份均被 Git 忽略。本轮没有 Git 提交、推送或赛事提交。

## 验证结果

1. 回归测试 **158 项通过，32.13 秒**，覆盖本地模型缓存、GPU 参数、异常向量、模型空间隔离、删除联动、配置变化/取消时不提交、请求合并和故障回退等。普通测试不加载用户真实模型。
2. `scripts/verify_bge_m3.py` 实际加载模型、编码三段合成英文证据，并进行两道中文检索。向量均为 1024 维、范数约 1；当前两道混合检索首条均命中预期。详见 `BGE_M3_CHECK.json`。
3. 保留首次失败记录 `BGE_M3_INITIAL_CHECK.json`：泛化表述“这项研究采用了哪种计算设备”的纯向量排序将硬件证据放在第二。新增通用硬件同义词后，混合检索首条正确；当前报告同时保留纯向量排序，未声称该纯向量失误消失。第二道动量系数问题与英文证据没有词法重叠，依靠语义召回。
4. 主服务 `8765` 的原文献库 **28 篇 / 10,299 个文本块全部索引完成**，1024 维，抽样向量范数约 1。原有论文未删除或重新导入；39 份资料包所在的独立 `8766` 测试库未在本轮补建。详见 `BGE_M3_LIBRARY_CHECK.json`。
5. 索引后实际调用 MiMo Pro 回答 Transformer 的训练硬件与 Adam 参数，HTTP 200，返回 8 块 NVIDIA P100、β1=0.9、β2=0.98、ε=10^-9，并带第 7 页原文引用；执行记录明确使用 BGE-M3 混合检索。
6. 浏览器实际打开配置页，显示本地 CUDA 模型、10,299/10,299 索引就绪，点击补建后保持相同覆盖率。进度没有变化时不重建控件，保留键盘焦点。截图 `screenshots/bge-m3-ready.jpg`。

## 范围与复现

本轮接入稠密语义检索；BGE-M3 的 sparse / ColBERT 输出、专业重排和大规模召回评测不在本次验证中。PDF 上传去重继续使用现有内容对比逻辑。这些小样本结果不构成所有语义问题、跨文推理及事实正确性的保证。

安装、下载和配置命令见 README 的模型配置部分。`scripts/verify_bge_m3.py` 不调用付费模型；`scripts/verify_bge_library.py` 等待主库补建完成并产生一次真实 MiMo 调用。

官方来源：[模型说明](https://huggingface.co/BAAI/bge-m3)、[固定版本权重](https://huggingface.co/BAAI/bge-m3/blob/5617a9f61b028005a4858fdac845db406aefb181/pytorch_model.bin)。
